Alpaca Study Buddy

This proof of concept turns a student's pasted notes into a small quiz, flashcard set, or both. The browser holds the active session in memory, while the server calls Groq through the OpenAI-compatible SDK and validates the response with Zod before it reaches the UI.

Run it: copy .env.example to .env, add a Groq key (and optional database URL), then run npm install and npm run dev. This map is an offline snapshot from commit 83d2a8f.

Reference route

  1. Start at Setup.generate in src/App.tsx. It sends the note, selected mode, and count to POST /api/generate.
  2. Follow the route in server/index.ts to generateStudySession in server/openai.ts. The prompt requests JSON, then Zod checks the decoded object and item counts.
  3. Return to ReviewView in src/App.tsx. It selects QuizReview or FlashcardReview, then sends the user to CompletionView and FullSessionReview.

To change this, start here

  • Change the setup wording or default item count: Setup in src/App.tsx.
  • Change generated fields or safety rules: generateRequestSchema and studySessionSchema in server/validation.ts, then the prompt in server/openai.ts.
  • Change completion actions: CompletionView and the ReviewView state transitions in src/App.tsx.
  • Change the friendly visual language: src/styles.css and AlpacaCompanion.

A practice to reuse

When Groq returned malformed JSON, the build used the observed provider response to narrow the fix: describe the required fields plainly, parse the response, and keep Zod as the final boundary. On another project, connect a user-visible acceptance criterion to a real response check before trusting external data.
